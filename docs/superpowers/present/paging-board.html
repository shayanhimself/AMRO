    Ship check
    
      
    Five questions. Each one is a thing that bit this codebase for real.
    
    
    
    
    
  
    

    


    
  
    
    
    
      
    Three guarantees
    
      
    Properties the board holds, and the mechanism that holds each one.
    
    
    
    
    
      
    
        every write lands
        
    The reader always hears it
    
        
    
          Room begins watching a table while the first read of it is still running, and a fetch
          landing in that window would reach nobody. That window is every cold start.
        
    
        
    
          So the local source holds the paged reads it handed out under each key and invalidates
          them itself after writing. That is the dashed wire on the board.
        
    
      
    
      
    
        one place per movie
        
    A repeat keeps its first place
    
        
    
          The provider re-ranks between calls, so a movie stored near the end of one fetch arrives
          again at the start of the next. Two rows under one id is a duplicate key, and the list
          refuses it.
        
    
        
    
          A unique index on (queryKey, movieId) drops the repeat, and the
          append reads its start position inside the writing transaction, because a repeat takes no
          place.
        
    
      
    
      
    
        the reader stays put
        
    A rebuild lands where they are
    
        
    
          Room keys by row offset, and with placeholders off an anchor counts from the first loaded
          row, so a refresh key is the reader's row plus the window start, minus half a first read.
        
    
        
    
          That is what keeps an append from moving anyone: a cold start and 40
          swipes cost 15 requests in all, in order, and the list stops when
          the scrolling does.
        
    
      
    
    
    
  
    

    


    
  
    
    Numbers measured on a Pixel 10 emulator against live TMDB, data cleared between runs. The board
    runs the app's own rules: a fetch asks for 50 movies and whole pages of twenty come back, a source
    with nothing below the window wakes the mediator, and every write rebuilds the snapshot.
