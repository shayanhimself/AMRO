The zero column is not the whole story

0* is Streaming Availability: the URL is finished, but signed and expiring, so it is free to build and not free to keep. Three of the four sources that hand over a finished URL attach a condition to using it. Watchmode disclaims any licence to the image and any guarantee it stays up. Fanart.tv serves http://. Simkl asks that you route every request through wsrv.nl rather than its own origin. Trakt goes furthest: hotlinking is blocked outright and images are required to be cached server-side, which a client-only app cannot do.

The size sits inside the returned path, and the API hands you exactly one of them. Substituting the token works — thumb, medium and full all resolve, original is a 404 — but that set is documented nowhere, so a client that wants a bigger poster than the one it was given is guessing. Everything is served as WebP regardless of the .jpg or .png in the path.

The missing scheme is a real failure, not a curiosity

curl accepts walter-r2.trakt.tv/… and silently assumes a scheme, which is why the value looks usable from a shell. An Android image loader does not: HttpUrl.parse and Uri.parse treat a scheme-less string as a relative reference, so the load fails or resolves against the wrong base. The prepend is mandatory. Trakt also blocks hotlinking outright and requires images be cached server-side, which a client-only app cannot satisfy.

Watchmode — four fields, no published sample Spec

Four image fields on TitleDetails, all format: uri, all nullable: poster, posterMedium, posterLarge, backdrop. Note the casing — two lowercase, two camelCase, in an object whose every other key is snake_case.

// the example value in the OpenAPI document, for all four fields
"poster":       "http://www.some-poster-site.com/image.jpg"
"posterMedium": "http://www.some-poster-site.com/image.jpg"
"posterLarge":  "http://www.some-poster-site.com/image.jpg"
"backdrop":     "http://www.some-poster-site.com/image.jpg"

That placeholder is the vendor's own published example for every image field, including AutocompleteResult.image_url. There is no real sample to build from and no host to name, because there is no single host: each field's description says the URL "May point to a third-party host. Watchmode does not grant any license to the underlying image." The API description adds that it "does not guarantee ownership, copyright status, availability, or permitted use". The list endpoint carries no images at all — TitleListItem is ids and text only.

A signed URL is a lease, not an address

Every one of these is a CloudFront signed URL carrying an expiry, a signature and a key id, and removing the query returns 403. Two consequences for a client that persists API responses: a stored URL goes dead on its own schedule regardless of your cache policy, and the URL is roughly 466 characters, so twenty of them is about 9 KB of signature per title in the database. Cache the bytes, not the link.

Two more shape details visible in that response. tmdbId is "movie/155" — a type-prefixed string, not the bare integer every other source uses — and id is the string "68". And rating is 89 for a film IMDb rates 9.0, so the scale is 0–100 even though the field's own documentation states no scale at all.

The suffix is a token, not a width, and the tokens are not ordered by size: _m comes back larger than _w, because _w is a cropped landscape crop of a poster. Film posters are copyrighted, so they are usually absent.

Section 7

Gotchas, collected

Images

  • TMDB rejects an unlisted size with 400, and the legal set comes from /configuration, not a constant.
  • TMDB poster ratios span 0.657–0.75 and logo ratios span 2.386–9.364. Fixed boxes crop real art.
  • Trakt image URLs have no scheme. Prepend https:// or the load fails, and its size tokens (thumb, medium, full; original is a 404) are documented nowhere.
  • Trakt forbids hotlinking and requires server-side caching, which a client-only app cannot satisfy.
  • Watchmode image URLs point at third-party hosts under no licence, with availability explicitly not guaranteed, and the vendor publishes only a placeholder example.
  • Watchmode mixes three casing conventions in one object: poster, posterLarge, imdb_id.
  • Simkl needs domain, prefix, fragment, size suffix and extension in order; two documented poster heights vary, and _m comes back larger than _w.
  • JustWatch profiles are a closed, unpublished set. s66 and s999 both 400.
  • Cinemeta's large poster returns WebP while its other sizes return JPEG, and nine of its twelve size choices return a byte-identical image.
  • Fanart.tv serves http:// though the host does support TLS, and types likes as a string, so "7" sorts after "51".
  • Wikidata's P18 is a photograph of the subject, not a poster, and resolves through a redirect.
  • IMDb's bulk datasets contain no images in any of their seven files, though the public suggestion endpoint returns an Amazon URL whose _V1_ segment is an open transform slot.

Ratings

  • TMDB's 0.0 means unrated. Branch on vote_count, never on the value.
  • OMDb returns every field as a string, missing values as "N/A", and vote counts with thousands separators.
  • Wikidata bakes the denominator into the value: "74/100", "8.1/10", "87%".
  • Simkl's provider keys appear as both imdb and IMDB in its own examples, and rank is sometimes an integer and sometimes an object.
  • JustWatch mixes 0–10, 0–100 and 0–1 in one flat object and gives a vote count to only one provider.
  • Watchmode's user_rating and critic_score are adjacent keys on different scales, beside two percentiles that are ranks.
  • Streaming Availability's rating blends unnamed sources and states no scale; its own published example returns 89, so it is 0–100.
  • MDBList's OpenAPI declares ratings as an untyped array of untyped objects.
  • TheTVDB's score has no documented range, no vote count, and shares its name with an unrelated artwork score.
  • TMDB's per-image vote_average and vote_count share names with the film's and mean something else.
  • popularity is not a rating anywhere it appears.

IMDb ids

  • Present on every detail endpoint in the survey.
  • Absent from TMDB list responses, the one place it costs an extra call.
  • TMDB's external_ids returns "" for one missing id and null for another in the same object.
  • TheTVDB identifies the source by integer, not by key name.

Section 8

What this means for AMRO

The brief's post-MVP ambition to collect from multiple sources hits the same wall in all three fields, and the fix has the same shape as the genre recommendation in the companion report: resolve at the source boundary into an app-owned type, and never let a source's representation reach the UI.

Images

Model an app-owned image reference holding a resolved absolute URL per size bucket the UI actually asks for, and give each source's mapper the job of building it. TMDB concatenates base and size, Trakt prepends a scheme, Simkl assembles five pieces, JustWatch substitutes two placeholders, Cinemeta and Streaming Availability pass through. Only the mapper should ever know which. Keep the returned aspect_ratio where a source gives one, because TMDB's posters are not uniformly 2:3.

Ratings

Model a rating as value + scale + vote count + provenance, all four non-optional in the app type. A bare Float cannot distinguish 8.8 from IMDb, 86 from Rotten Tomatoes and 0.97 from JustWatch, and it cannot express "unrated" — which TMDB encodes as 0.0 and Streaming Availability cannot express at all. Sort and filter on the normalised value; display the original scale, because a user who knows a film is 87% on Rotten Tomatoes will not recognise 8.7.

The join key

The IMDb id is the only identifier on the detail record of every source surveyed, and it is stable, opaque and globally unique. Make it the cross-source identity in the domain model. Two consequences: TMDB list responses do not carry it, so a multi-source pipeline either keys on TMDB ids internally and resolves to tt… at detail time or accepts one extra call per title; and both Cinemeta and Watchmode hand out IMDb-to-TMDB mappings for free, so the join need not be paid for at TMDB rates.

The licence constraints bind hardest on images

TMDB caps caching at six months and forbids commercial use without a written agreement. OMDb is CC BY-NC 4.0. IMDb's datasets are non-commercial. Trakt requires server-side caching and blocks hotlinking. Watchmode disclaims any licence to the images it links. Streaming Availability ships the best-formed URLs in the survey, but they are CloudFront leases that expire on their own schedule, so what you cache is the bytes, never the link. No source in the survey both hands over durable URLs and attaches no rule the app has to work around.
