Section 1

The field, and what each source is actually for

Excluded on purpose

JustWatch's GraphQL endpoint answers unauthenticated requests and returns the best-shaped data in this survey: IMDb score, TMDB score and Tomatometer in one response, with per-country offers. It is undocumented, unversioned, and not offered for third-party use, by a company that sells this exact data. Watchmode and Streaming Availability are the licensed version. Its genre model is still worth studying, and appears below.

What actually breaks when a second source arrives

  • TMDB says Science Fiction. IMDb, OMDb and Cinemeta say Sci-Fi. Trakt says science-fiction. Three spellings of one concept across four sources.
  • TMDB has TV Movie as genre id 10770. IMDb has no such genre; it is a titleType. The same distinction is a genre in one model and a type in another.
  • IMDb carries Short, News, Talk-Show, Game-Show, Reality-TV. TMDB carries none of them. Trakt adds nine more TMDB has no slot for, including anime, donghua, holiday, indie, road, and an explicit none.
  • JustWatch merges what TMDB keeps apart: act is Action & Adventure, trl is Mystery & Thriller. A round trip through JustWatch loses the Action/Adventure distinction permanently. Its eur bucket, Made in Europe, is not a genre at all: it is provenance wearing a genre's clothes, because the vocabulary was designed for a filter row rather than for cataloguing.
  • Trakt is the only two-level system. Nothing else can express that heist is a kind of action.
The trap inside Cinemeta

Its manifest declares 19 filterable movie genres. Its meta objects return the full IMDb 28: a live fetch of Big Buck Bunny came back ["Animation", "Short", "Comedy"], and Short is not in the filter list. A UI built from the manifest shows items carrying genres it cannot filter on.

Only Watchmode ships the cross-walk as data, via a tmdb_id field on every genre row, set to 0 where no TMDB equivalent exists. Everyone else leaves the mapping to you.

Section 3

Release status: one word, three meanings

Only four of the twelve sources carry a title's release or production state at all, and no two represent it the same way. The word is also overloaded: every TheTVDB response wraps its payload as {"data": …, "status": "…"}, where that outer status reports whether the call succeeded. OMDb's Response is the same idea under another name. A lookup reaching for status on a TheTVDB response finds the envelope, not the movie.

Where both movies and TV exist, the vocabularies diverge again. Trakt's show statuses are returning series, continuing, in production, planned, upcoming, pilot, canceled and ended. Simkl reuses ended and airing for shows, and keeps a separate set for a user's own list: watching, plantowatch, completed, hold, dropped.

Measured, TMDB trending page 1

All 20 details behind the current trending page were fetched: 19 Released, 1 Post Production. Roughly one trending film in ten has not come out yet, which is why vote_count is zero for 11% of them and budget and revenue are empty for over 40%. status is the field that explains the missing data, and it is the field the list endpoint does not send.

TMDB gives title-case strings, Trakt and Simkl give lowercase strings, TheTVDB gives a nested object with an id. A shared release-status type in the domain needs per-source parsing, exactly like the genre vocabularies one layer up. And because TMDB carries status on detail but not on list items, a list-level decision that depends on it, such as suppressing a rating block for an unreleased film, either waits for the detail fetch or infers the state from vote_count and release_date.

Section 6

Joining across sources

Every source here except the IMDb bulk files speaks IMDb id, and every one except OMDb, IMDb bulk and Fanart.tv speaks TMDB id. Hold the TMDB id as the primary key, carry imdb_id alongside it, and every other source is one hop away.

TMDB id
  ├─ /movie/{id}.imdb_id ──> IMDb id ──> OMDb, Cinemeta, Simkl, MDBList
  ├─ Trakt .ids{trakt, slug, imdb, tmdb} ──> everything Trakt touches
  ├─ TVDB /search/remoteid/{id} ─────────> TVDB id
  ├─ Watchmode /search?search_field=tmdb_movie_id
  │            or the daily title_id_map.csv
  ├─ Streaming Availability /shows/movie/{tmdb_id}
  └─ Wikidata P4947, or P345 for IMDb

Watchmode's title_id_map.csv, refreshed daily with Watchmode, IMDb and TMDB ids for every title, is the only bulk mapping offered anywhere in this list.

Section 7

What to do about it
Two TMDB facts worth stating out loud

Caching is capped at six months by the terms. An unbounded offline store is a licence breach, not merely a design trade-off, so a future offline mode needs an eviction policy for legal reasons as well as storage ones. And commercial use needs a written agreement. A hiring-assignment MVP is fine; a business built on it is not, without signing something.

GoalSourceWhy it, and not the alternative
Critic scores, cheapest pathOMDbRotten Tomatoes and Metacritic in one call, keyed by an imdb_id already held. Everything is a string, so parse strictly.
Many ratings at onceMDBListNine providers including Letterboxd and Roger Ebert. 1,000/day free, 250,000/day for €5 a month.
Where to watch, shipping commerciallyStreaming AvailabilityCommercial use on the free tier. Watchmode starts at $349/mo for any commercial use at all.
Where to watch, maximum coverageWatchmode367 providers, episode-level deep links, and a genre table that maps itself to TMDB. Budget for the credit multipliers.
Trending, with better pagingTraktConfigurable page size removes the whole unstable-paging problem. Best join key here.
Artwork, awards, per-country ratingsTheTVDBFree below $50k revenue, and the only revenue-tiered pricing in the field.

The one architectural change this survey argues for

Resolve each source's genre representation into an app-owned genre type at the source boundary, instead of letting TMDB's integer ids reach the domain. It costs nothing today, with one source and one vocabulary. Twelve vocabularies, no two of which agree, is what "collect data from multiple API sources" actually means in this field.

Section 8

Reproduce the live findings
# IMDb: 28 genres, measured across 268,084 real rows
curl -s -r 0-6000000 "https://datasets.imdbws.com/title.basics.tsv.gz" \
  | gzip -dc 2>/dev/null \
  | awk -F'\t' 'NR>1{n=split($9,a,","); for(i=1;i<=n;i++) if(a[i]!="\\N") g[a[i]]++} \
                END{for(k in g) print g[k]"\t"k}' | sort -rn

# TMDB: status across every detail behind trending page 1
for id in $(curl -s -H "Authorization: Bearer $TMDB_TOKEN" \
    "https://api.themoviedb.org/3/trending/movie/week" \
    | python3 -c 'import sys,json;print(" ".join(str(r["id"]) for r in json.load(sys.stdin)["results"]))'); do
  curl -s -H "Authorization: Bearer $TMDB_TOKEN" "https://api.themoviedb.org/3/movie/$id" \
    | python3 -c 'import sys,json;print(json.load(sys.stdin)["status"])'
done | sort | uniq -c | sort -rn

# JustWatch: 19 merged genre buckets
curl -s -X POST https://apis.justwatch.com/graphql -H 'Content-Type: application/json' \
  -d '{"query":"{genres{shortName translation(language:\"en\")}}"}'

# Cinemeta: filter vocabulary (19) against item vocabulary (28)
curl -s https://v3-cinemeta.strem.io/manifest.json
curl -s https://v3-cinemeta.strem.io/meta/movie/tt1254207.json   # returns "Short"

# Wikidata: 693 film-genre items
curl -s -G https://query.wikidata.org/sparql -H 'Accept: application/sparql-results+json' \
  -H 'User-Agent: AMRO-research/1.0' --data-urlencode \
  'query=SELECT (COUNT(DISTINCT ?g) AS ?c) WHERE { ?g wdt:P31/wdt:P279* wd:Q201658 . }'

# Machine-readable contracts
curl -s https://thetvdb.github.io/v4-api/swagger.yml       # OpenAPI 3.0.0, v4.7.10
curl -s https://api.mdblist.com/schema/                    # OpenAPI 3.0.3
curl -s https://jsapi.apiary.io/apis/trakt.apib            # API Blueprint, 854 KB
curl -s https://api.simkl.org/llms.txt                     # current Simkl doc index

# Auth models, confirmed by unauthenticated probe
curl -s "https://www.omdbapi.com/?i=tt1375666"       # 401, "No API key provided."
curl -s "https://api.watchmode.com/v1/genres/"       # 401, "Please enter a valid API key."
curl -s "https://api.mdblist.com/tmdb/movie/27205"   # 401, names both apikey and bearer
curl -s "https://api.trakt.tv/movies/inception-2010" # 403 Cloudflare, no trakt-api-key
